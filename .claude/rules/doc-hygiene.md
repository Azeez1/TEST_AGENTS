# Documentation & Memory Hygiene Rules

**Premise:** documentation is a cache of understanding. Every cache needs an invalidation strategy. These rules ARE that strategy. (Born from the 2026-07-12 Factory Audit: 4 conflicting agent counts, 19 stale governance docs, phantom tool declarations.)

## Single Source of Truth
- A fact (count, roster, list, path) lives in EXACTLY ONE file. Everything else links to it.
- Roster/skill/MCP counts live in CLAUDE.md's table. NEVER restate them in another doc — write "(see CLAUDE.md)" instead.
- Before writing any fact into a doc, ask: does this already live somewhere? Yes → link. No → pick its one home.

## Generate, Don't Hand-Maintain
- Anything derivable from the filesystem (mirrors, registries, counts) is script output, never hand-typed.
- `.codex/` is generated by `/sync-codex` ONLY. Hand-editing the mirror is forbidden — fix the `.claude/` source and re-run the sync.
- If you find yourself updating the same derived content twice, write the generator.

## Machine-Check Every Checkable Claim
- If a doc or agent makes a verifiable claim (tool exists, file is read, server is enabled), a checker script must verify it on a schedule.
- Current checkers (mandatory step 1 of `/agent-health`, runs Mondays):
  - `python tools/lint_agent_declarations.py` — every tools:/skills: entry resolves to reality
  - `python tools/check_codex_drift.py` — .codex mirror is FRESH vs .claude sources
- Adding a new claim class? Add a checker or don't write the claim.

## Document AFTER Shipping
- Never document a planned API/tool as if it exists. If writing ahead of the build, prefix with `PLANNED:` so future readers know it is a promise, not a fact.
- After implementation lands, reconcile the doc with what actually shipped (names change during builds).

## Doc Lifecycle: live → archived → gone
- Any doc untouched for 3+ months gets a DECISION at the monthly re-cert: recertify, archive, or merge. "Default keep" is not an option.
- Archive = `git mv` to `docs/archive/` (history preserved) + repoint inbound links with an *(archived)* marker.
- Before archiving, grep for inbound references: runtime reads (agents/hooks/scripts) block archiving; "see also" index lines do not.
- A wrong doc is worse than no doc: an absent doc forces a look at reality; a stale doc produces confident errors. When in doubt, delete the claim.

## Memory Hygiene
- Every memory/config file needs a WRITER and a READER. Write-only files are waste; read-references to missing files are silent failures. Orphans get deleted or wired at re-cert.
- Memory entries carry dates. Old entries are point-in-time observations — verify against reality before trusting.
- Wrong memory gets DELETED, not corrected-by-appending.
- MEMORY_SYSTEM.md inventories must match disk. Adding/removing a memory file means updating the inventory in the same session.

## Monthly Re-Cert Ritual (~30 min, or at every model release)
1. **Census** — regenerate counts from filesystem into CLAUDE.md
2. **Checkers** — confirm the Monday linter + drift checker are green (automated)
3. **Harness Bottleneck Test** — re-justify every model pin and guardrail against the current model generation
4. **Memory sweep** — orphans deleted or wired; phantom read-targets created or de-referenced
5. **Doc decay** — 3-month-stale docs get their lifecycle decision

**One-line summary: move truth-keeping from human memory into structure — one home per fact, generators for derivables, checkers for claims, lifecycles for docs.**
