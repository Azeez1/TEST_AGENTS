§ 02

The three core frameworks

One produces. One refines. One protects.

Framework 1 — The Core Four

ContextWhat the model can SEE — files, memory, prior messages
ModelWhich Claude + reasoning depth (Opus / Sonnet / Haiku)
PromptThe instruction — slash commands, agent definitions, chat
ToolsWhat the model can DO — Read/Write/Bash, MCP, subagents
DIAGNOSTIC ORDER — Tools first (did agent say can't?) → Context second (missing info?) → Prompt third (solved wrong problem?) → Model last (shallow output?). Most engineers do this in reverse.

Framework 2 — The 12 Leverage Points (6 Clusters)

A · Knowledge LayerCLAUDE.md · Agent YAML
B · Invocation LayerSlash commands · Skills
C · Delegation LayerSubagents (Task tool)
D · Capability LayerMCP servers · Tool permissions
E · Enforcement LayerHooks · Output routing
F · Quality LayerSchemas · Validators · Stdout logs

Your cluster strength: A/B/D strong · C/E/F weak. Knowledge-layer-heavy, enforcement-and-quality-layer-light.

Framework 3 — The 7 Guardrails (your synthesis)

1. Input validationValidate what comes INTO the agent
2. Output validationValidate what comes OUT before downstream use
3. Resource limitsCost / time / token caps
4. Output routingMap output to filesystem location
5. HooksDeterministic gates
6. Tool permissionsAllow / deny / ask rules per tool
7. SandboxExecution isolation (Docker, restricted FS)
WHY THIS FRAMEWORK MATTERS — Demos prevent embarrassment. Guardrails prevent bankruptcy. Resource limits are the guardrail every demo skips. Yours is the first framework to elevate them as a distinct concept.
§ 03

The fourteen lessons

LESSON 01 · 1H
The Core Four
CONCEPT
Every AI output = Context + Model + Prompt + Tools. When output is bad, one of these four is the cause.
WHY FOR YOU
80% of engineers reach for the prompt. The real fix is usually Context (wrong files loaded) or Tools (missing capability).
DONE WHEN
Your next debug starts with 'context or tools?' not 'let me rewrite the prompt.'
LESSON 02 · 1H
The 12 Leverage Points
CONCEPT
12 places to inject signal: CLAUDE.md, agent YAML, slash commands, skills, subagents, MCP, hooks, permissions, output routing, schemas, validators, stdout. Group into 6 clusters.
WHY FOR YOU
You use 1-6 and 8-9 actively. Barely use 7 (one hook), 10-12 (no schemas, no validators). Unused points = highest-ROI work.
DONE WHEN
Prioritized list of which leverage points to add next.
LESSON 03 · 1.5H
Plan First, Execute Second
CONCEPT
Before asking an agent to DO, ask it to PLAN. Plan goes in a file. You review (5 min). Agent executes against it.
WHY FOR YOU
Multi-step work without explicit plans = silent deviations. Plans are exception detectors that catch issues at the cheapest possible time.
DONE WHEN
Three of your skills do plan-then-execute instead of execute-blind.
LESSON 04 · 2–3H
PITER / AFK Agents
CONCEPT
Pipeline pattern: Plan → Implement → Test → Evaluate → Review. Each phase has a gate. You walk away.
WHY FOR YOU
Your 17-episode YouTube backlog is the ideal PITER candidate. Each episode follows the same 5-phase shape.
DONE WHEN
You run a PITER script for one weekly workflow and walk away for 30 min while it produces a script + storyboard.
LESSON 05 · 2H
Closed Loop Prompts ★
CONCEPT
Self-correcting loop. Agent runs → validator checks → if fail, agent reads the failure and patches → re-validate → loop up to N retries → escalate.
WHY FOR YOU
Your PE validation gate is half a closed loop. The other half is auto-fix-and-retry instead of human intervention. Stop being the manual retry button.
DONE WHEN
A PE diagnosis can fail validation up to 3 times and still produce a valid PDF without your involvement.
LESSON 06 · 2–3H
Specialized Subagents ★
CONCEPT
The agent that WRITES should not be the agent that REVIEWS. Three roles: Implementer, Reviewer (Write/Edit excluded), Documenter. The tool restriction IS the separation.
WHY FOR YOU
Zero pure reviewer subagents today. Cross-agent review is the highest-leverage QA play you're missing.
DONE WHEN
Top-3 most-used pipelines all spawn a reviewer subagent (Write/Edit-restricted) before declaring done.
LESSON 07 · 3H
ZTE — Zero Touch Engineering
CONCEPT
Spectrum: in-loop → out-loop → ZTE. ZTE = pipeline ships from trigger → final output with zero human touches. Requires closed loops + reviewers + cron + escalation + audit log.
WHY FOR YOU
lead-gen-cleaning is the cleanest first target. Trigger ready (slash command), sink ready (Sheet), quality bar clear, failure recoverable.
DONE WHEN
A lead-gen run happens at 9am Monday without you launching it. Telegram ping at 9:15am. Repeats next Monday. And next.
LESSON 08 · 2H
The Agentic Layer
CONCEPT
Many agents + hooks + closed loops = distributed system. Distributed systems need infrastructure: structured logs, trace IDs, cost tracking, failure rates, fallback policies.
WHY FOR YOU
You operate 65 agents blind today. Can't answer 'which agent costs me most this week?' That's the operator mindset gap.
DONE WHEN
You can answer 'which agent costs me most this week?' in one query against your own JSONL data.
LESSON 09 · 2H
Context Engineering (R+D)
CONCEPT
Retrieve only what's needed + Discard aggressively. Big context costs money, slows down, makes the model dumber. 12 techniques: lazy load, glob over read, ephemeral working files, fresh-context subagents, MCP filtering, memory curation.
WHY FOR YOU
Your CLAUDE.md is big. MEMORY.md is bigger. Half is stale. Every prompt loads all of it. Cost AND quality compound negatively.
DONE WHEN
MEMORY.md under 4KB with a weekly archiving rhythm.
LESSON 10 · 2H
The 7 Prompt Levels
CONCEPT
Sophistication ladder: plain → structured → few-shot → templated → chained → meta-prompt → self-improving meta-prompt. Each level abstracts the layer below.
WHY FOR YOU
Most of your skills are level 2-3. Slash commands level 4. Nothing is 5+. Meta-prompts (level 6) are where 10× productivity lives.
DONE WHEN
One production meta-prompt that generates other prompts you actually use.
LESSON 11 · 2H
Domain-Specific Agents
CONCEPT
Specialists outperform generalists on narrow tasks. Encode domain knowledge into the agent. Strict scope, glossary, examples, validation rules, output schema.
WHY FOR YOU
Your 6 teams are domain agents at team level. Within teams, agents overlap. MARKETING has 18 agents — you can't state in one sentence what each one owns.
DONE WHEN
Each MARKETING agent has a non-overlapping domain stated in one sentence.
LESSON 12 · 3H
Multi-Agent Orchestration
CONCEPT
One orchestrator agent receives complex task, decomposes it, dispatches in parallel where possible, aggregates results. Components: orchestrator + specialists + coordination + observability.
WHY FOR YOU
Verified: only 2 of 65 agents have Task in tools. router-agent, cto, cfo-agent, sales-manager, rfp-agent are orchestrators in name only.
DONE WHEN
One real workflow runs as ≥3 parallel subagents instead of one sequential agent.
LESSON 13 · 2H
Skills as Learned Behavior
CONCEPT
Agents forget. Skills are persistent procedures the agent loads when needed. Act-Learn-Reuse: agent acts, captures pattern as skill, reuses next time.
WHY FOR YOU
28 skills, all hand-built. Missing pattern: agent writes its OWN skills from successful runs. Library grows as a side effect of operations.
DONE WHEN
Captured ≥2 new skills from real work (not designed in advance) within 30 days.
LESSON 14 · 4–8H + 30D
Capstone — Codebase Singularity
CONCEPT
Synthesis. Pick one workflow. Apply every lesson (1-13). Run it untouched for 30 days. Prove the system works.
WHY FOR YOU
This is Dux Machina's delivery moat. Anyone can sell agentic consulting. Almost nobody can demo a codebase that ships features while the founder sleeps.
DONE WHEN
Live screen recording of pipeline running with zero human input for 30 days. That becomes the Dux Machina pitch deck slide.
