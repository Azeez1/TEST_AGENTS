# Three-Pillar Learning Protocol

**Created:** 2026-08-22  
**Source:** Oracle second-brain query plus local learning files.

## Core Verdict

EZ learns fastest when learning is forced into a real artifact.

The pattern from the second brain:

1. Prime the domain.
2. Build the logic layer.
3. Encode by simplifying, comparing, connecting, and grouping.
4. Explain it plainly with a Feynman check.
5. Deploy it against a real business or architecture problem.
6. Review the rep with volume x feedback.

Active recall matters, but it is secondary. Encoding is the main lever. Retrieval refills the bucket; encoding patches the leak.

## The Merge

Do not study the three pillars as three separate school subjects.

Train one repeated motion:

`Business diagnosis -> system design constraint -> agentic implementation/eval`

| Pillar | What It Contributes | Output |
| --- | --- | --- |
| Business Solutioning | Problem, workflow, value, stakeholder risk | WISER map, constraint diagnosis, KPI |
| System Design | Reliability, scale, security, data, cost, latency, operations | Architecture diagram, data/API boundaries, runbook |
| Agentic Engineering | LLM placement, tools, RAG, memory, guardrails, evals | DBAC design, schema, eval, human gate |

## The Weekly Artifact Rule

One artifact per week, not one topic per week.

Every weekly artifact must contain:

- Quantified business diagnosis
- Constraint-driven system design
- Agentic DBAC implementation
- Check layer: eval, guardrail, human review, log, or metric

## 7-Day Protocol

### Day 1: Pick One Real Problem

Choose one real target or workflow.

Write three priming questions:

- Business: What pain or value gap matters?
- System: What constraint or failure mode matters?
- Agentic: What should the AI do, and how will we check it?

### Day 2: Build The Logic Layer

Make a one-page scaffold.

Use:

- WISER for workflow
- System Design limits for constraints
- DBAC for agent design

Do not add details yet. Build the shelves before stacking books.

### Day 3: Encode Deeply

Run the Sung encoding loop:

- Simplify: what is the plain mechanism?
- Compare: what is this like and unlike?
- Connect: what changes because this exists?
- Group: which bucket does this belong in?

Add exactly:

- One business framework
- One architecture principle
- One agentic pattern

### Day 4: Feynman Check

Explain the artifact with no notes.

Target:

- 10 minutes max
- Plain English first
- Jargon second

Where you stutter is the study target.

### Day 5: Build The Smallest Usable Version

Pick one:

- Diagnosis PDF
- Architecture sketch
- Agent workflow
- Output schema
- Eval rubric
- Runbook

The artifact can be rough. It must be real.

### Day 6: Interleave Across Three Cases

Test the same model against three contexts:

- PE target
- Internal ops workflow
- Client AI automation

This prevents brittle knowledge that only works in one framing.

### Day 7: Review With Volume x Feedback

Ask:

- What improved?
- What failed?
- What was fuzzy?
- What becomes next week's checklist?

Do not start a new topic until the feedback is captured.

## 90-Day Principle

The 90-day sprint is not:

> Learn business, then learn system design, then learn agents.

The 90-day sprint is:

> Produce 12 weekly artifacts that each merge business diagnosis, system architecture, and agentic implementation.

After 12 reps, the skill is no longer theoretical. It becomes an operating system for turning client ambiguity into engineered AI systems.
