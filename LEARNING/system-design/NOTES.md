## Confirmed preferences
- **First Principles + Feynman are mandatory** (baked into the skill). FP decides what/order; Feynman decides delivery.
- Plain English + everyday analogy FIRST, then the technical term labeled "the fancy name is ___".
- One idea per lesson. No walls of text. Info-overload is a real failure mode for EZ.
- Each lesson ends with a teach-back so gaps surface.
- Blend goal: ground in classic distributed systems, then apply to AI/agent architecture (EZ's own builds = great concrete examples).

- Preferred lesson flow: prime first, then explain one concept, apply it to a concrete system, force a short teach-back, patch only the miss, then move on.
- Default design-rep framework: **DRAWS** = Define the job -> Requirements -> Actors/Actions/Assets -> Wire the system -> Stress test the design. Use this before diagrams so EZ can separate features, constraints, data objects, storage choices, and tradeoffs.
- Short-term rep mode: train **DRAW** first and hold off on Stress Test until D/R/A/W feel automatic. The hardest reps are currently **A** (actors/actions/assets) and **W** (wiring/data paths).
- Current rep priority: run **W-first reps**. Pause S until EZ can split system lanes and wire them cold. Use D/R/A only as light setup when needed. Feedback should focus on lane identification, component placement, data ownership, read/write/async/live/file/report paths, and whether each component has a first-principles reason.

Grade W reps against the concepts already trained, and clearly label any extra components as **new toolbox items**, not failures. - Use fading scaffolds for design reps: first rep may include a skeleton, second rep should use only guiding questions, third rep should be blank prompt only. Goal is blank-page identification, not filling in components Codex already named.
- Design-rep ladder: start with EZ's own systems first, then classic archetypes, then random prompts. Do not start with random mocks until DRAWS is automatic.
- Immediate practice mode: archetype reps. For each archetype, learn the default skeleton, common data objects, common bottlenecks, and how DRAWS customizes it.
