System Design W Primitives Toolbox

W means "wire the system." Do not memorize diagrams. Build them from primitives. A primitive is a basic building block that exists because a specific limit exists.

First-principles rule: every component must answer one question: what limit does this solve?

The Core Decision

If the lane needs... Draw this primitive Why
Truth that cannot be lost Primary DB The system needs one source of record.
Fast repeated reads Cache / Read Replica Do not make the source of truth answer every repeated read.
Search by words Search Index Normal DB rows are not optimized for text search.
Search by meaning Embedding Service + Vector DB The system needs semantic similarity, not exact keyword match.
Slow work after a request Queue + Worker The user should not wait while slow work finishes.
Tell many systems something happened Event Bus / PubSub One event can trigger many independent reactions.
Live updates to connected users Realtime Gateway / WebSocket The server needs to push updates without waiting for refresh.
Big binary files Object Storage + DB Metadata Files are large objects; metadata is queryable record data.
Analytics and reports Warehouse / Read Replica / Export Worker Heavy reporting should not hurt production writes.
Timed or recurring work Scheduler / Cron Some work starts because of time, not user action.
Multi-step business process Workflow / State Machine The system must remember where each item is in the process.
Money movement or audit-grade accounting Ledger / Transaction Log Balances must be explainable from immutable movements.
External systems calling you Webhook Receiver Another system needs a front door to send events.
Continuous high-volume events Stream Processor The system processes nonstop event flow, not one-off jobs.
Safe rollout or runtime behavior switch Feature Flag / Config Service Behavior changes without redeploying code.

Ingress Primitives

DNS

Maps a name like app.com to where traffic should go.

Draw when users access the system through a public domain.

CDN

Serves static assets near users.

Draw for images, videos, frontend files, public downloads.

WAF

Filters malicious web traffic before it reaches the app.

Draw for public web apps or sensitive internet-facing systems.

Load Balancer

Spreads traffic across app servers.

Draw when one server is not enough or uptime matters.

API Gateway

Routes API calls to backend services and applies API-level controls.

Draw for backend APIs, auth checks, rate limits, routing.

Storage Primitives

Primitive Plain English Common Software
Primary DB The official memory of the business. Postgres, MySQL, SQL Server, DynamoDB, MongoDB
Read Replica A copy used to remove read pressure from the primary DB. Postgres replica, MySQL replica, Aurora replica
Cache A fast temporary shelf for answers you need often. Redis, Memcached, Cloudflare KV
Search Index A special store for finding text fast. Elasticsearch, OpenSearch, Algolia, Typesense, Meilisearch
Vector DB A special store for finding similar meaning. Pinecone, Weaviate, Milvus, pgvector, Chroma
Object Storage A warehouse for large files. S3, Azure Blob, GCS, Cloudflare R2
Warehouse A reporting/analytics store. Snowflake, BigQuery, Redshift, Databricks
Ledger An audit-grade record of movements, especially money. SQL append-only table, QLDB-style ledger, event store

Product Pattern Primitives

Product Type Must-Think Primitive Core Question
Feed app Follow Graph + Home Feed Store How does a post get into followers' feeds?
Chat app Primary DB + Realtime Gateway How do we both save and instantly deliver messages?
Booking app Primary DB Transaction + uniqueness/locking How do we stop two users from taking the same scarce slot?
Document AI app Object Storage + Queue/Worker + Search Index How do we store files, process them later, and search extracted text?
Payments app Ledger + idempotency How do we make every money movement explainable and non-duplicated?
RAG app Embedding Service + Vector DB + model How does the model retrieve the right context before answering?
Analytics app Event Collector + Stream/Batch Pipeline + Warehouse How do raw events become dashboards and reports?
Integration app Webhook Receiver + Sync Job How do outside systems send or receive changes?

Lane Discovery Checklist

Before drawing components, ask: what are the 3-5 different promises this product makes? Different promises usually need different lanes. 
Durable write lane: what cannot be lost?
Fast read lane: what is viewed often?
Search lane: what must be found by text or meaning?
Async lane: what can happen after the user request?
Live lane: what must update without refresh?
File lane: what large object must be stored?
Report lane: what heavy query/export should not hit production?
External lane: what comes from or goes to another system?
Workflow lane: what moves through multiple business states?
Money/audit lane: what must be reconstructable forever?

Default W Template

Core user action:
Client -> Edge/LB -> Web App -> API Gateway -> Domain Service -> Primary DB

After durable write:
Primary DB/Event -> Event Bus/Queue -> Worker(s)

Fast reads:
Client -> API Gateway -> Read Service -> Cache/Read Replica

Search:
Client -> API Gateway -> Search Service -> Search Index

Files:
Client -> Upload Service -> Object Storage + DB Metadata

Live:
Client -> Realtime Gateway/WebSocket -> PubSub/Cache -> Client(s)

Reports:
Admin -> Report Service -> Replica/Warehouse -> Export Worker -> Object Storage

Short Rule

Do not ask, "What boxes do I remember?" Ask, "What promises does this product make?" Then choose primitives that satisfy those promises.
