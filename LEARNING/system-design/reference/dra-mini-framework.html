DRA Mini Framework

Use this before W. It helps separate non-functional requirements from assets without needing polished wording.

Functional means what the app must do. Non-functional means how well, safely, or reliably it must do it.

Non-Functional Requirements

Ask these six questions. Pick only the two that matter most for the product.

How fast?

Latency or freshness.

How correct?

What must never be wrong or duplicated?

How available?

When must the product stay usable?

How secure?

Who is allowed to do or see what?

How much load?

How many users, requests, or events must it handle?

What cannot be lost?

What needs durable storage?

Write each requirement in plain English:

The system must [constraint] [thing] [within condition or time].
The system must show a new driver location to the recipient within a few seconds.
The system must not attach a driver update to the wrong shipment.

Assets

An asset is a business thing the system needs to remember. Use these five noun buckets:

Who?

User account, employee, driver.

Thing?

Document, order, shipment.

State or change?

Status, version, location update.

Relationship?

Invitation, permission, assignment.

Evidence or history?

Receipt, comment, approval decision, audit record.

Asset or Component?

Business thing with fields, state, and a lifecycle? -> Asset
Machine that stores, moves, processes, or delivers that thing? -> W component

Shipment, bid, and document version are assets. DB, queue, cache, and WebSocket are W components.
